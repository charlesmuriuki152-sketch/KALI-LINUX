# Linux Network Troubleshooting Lab

## 1. Introduction

Network troubleshooting is an important skill in Linux system administration and cybersecurity. Linux provides several command-line utilities that help identify, diagnose, and resolve network connectivity problems.

In this lab, I practiced using Linux networking tools to investigate network configuration, verify connectivity, troubleshoot DNS resolution, and examine network routing.

**Operating System:** Kali Linux (WSL2)

**Lab Category:** Linux Networking

**Objective:** Learn how to identify and troubleshoot common network connectivity problems using Linux commands.

---

## 2. Step 1: Check Network Interface Configuration

The first step in troubleshooting network problems is checking whether the network interface is properly configured and has an assigned IP address.

### Command

```bash
ip addr show
```

Alternatively:

```bash
/sbin/ifconfig
```

### Explanation

- `ip addr show` displays network interfaces and their IP addresses.
- `ifconfig` displays network interface configuration.
- `lo` represents the loopback interface.
- `eth0` commonly represents the network interface in Kali WSL2.
- `inet` displays the IPv4 address.
- `UP` indicates that the interface is enabled.

### What to Check

- Whether the network interface exists.
- Whether the interface is UP.
- Whether an IPv4 address has been assigned.
- Whether the loopback interface is available.

### Observation

Record the network interface name, IPv4 address, and interface state from your terminal.

---

## 3. Step 2: Restart Network Services

If the network interface is not properly configured, restarting the network service may help restore connectivity.

### Commands

```bash
sudo systemctl restart NetworkManager
```

Other alternatives, depending on the Linux distribution, include:

```bash
sudo systemctl restart network
```

```bash
sudo service NetworkManager restart
```

```bash
sudo service network restart
```

### Explanation

These commands attempt to restart network management services to restore network connectivity.

**Note:** The appropriate command depends on the Linux distribution and its network management configuration. WSL2 manages networking differently from a conventional Linux installation.

---

## 4. Step 3: Obtain a Fresh IP Address

If the network interface is running but does not have an assigned IP address, a DHCP client can request an address from the network.

### Command

```bash
sudo dhclient eth0
```

Replace `eth0` with your actual network interface name.

### Explanation

- `sudo` executes the command with administrative privileges.
- `dhclient` requests network configuration through DHCP.
- `eth0` specifies the network interface.

DHCP (Dynamic Host Configuration Protocol) automatically assigns network configuration, including IP addresses.

---

## 5. Step 4: Check the System Hostname

A hostname identifies a computer on a network.

### Command

```bash
hostname
```

### Explanation

The command displays the hostname assigned to the Linux machine.

A hostname should be properly configured so that the system can identify itself on the network.

---

## 6. Step 5: Test Network Connectivity Using Ping

The `ping` utility checks whether a destination host is reachable over an IP network.

For this exercise, we use Google as the destination.

### Command

```bash
ping -c 3 google.com
```

### Explanation

- `ping` sends ICMP echo requests to the destination.
- `-c 3` limits the test to three packets.
- `google.com` is the destination hostname.

### Expected Output

Successful connectivity should produce replies from the destination, followed by packet transmission statistics.

For example:

```text
3 packets transmitted, 3 received, 0% packet loss
```

### Troubleshooting

If the command returns:

```text
ping: unknown host google.com
```

There may be a DNS resolution problem.

---

## 7. Step 6: Troubleshoot DNS Resolution Using Host

DNS (Domain Name System) translates domain names into IP addresses.

The `host` utility helps determine whether a domain name can be resolved.

### Command

```bash
host google.com
```

### Explanation

The command queries the configured DNS server to obtain information about the domain.

### Test an Invalid Domain

```bash
host l89xl28vkjs.com
```

An invalid domain should return an NXDOMAIN response, indicating that the domain does not exist.

### Query a Specific DNS Server

Google provides a public DNS server at `8.8.8.8`.

Run:

```bash
host google.com 8.8.8.8
```

This sends the DNS query directly to Google's public DNS server instead of using the system's default DNS server.

---

## 8. Step 7: Examine DNS Configuration

Linux systems commonly use `/etc/resolv.conf` to specify DNS resolver configuration.

### Command

```bash
cat /etc/resolv.conf
```

### Explanation

The command displays the configured DNS nameservers and other resolver settings.

You can also examine the hosts file:

```bash
cat /etc/hosts
```

### Explanation

The `/etc/hosts` file allows local associations between hostnames and IP addresses.

These entries are checked before DNS queries are made through the normal Linux name-resolution process.

---

## 9. Step 8: Use Dig to Investigate DNS

The `dig` utility provides detailed DNS query information.

### Command

```bash
dig google.com
```

### Explanation

The command displays DNS query information, including:

- DNS query status.
- Answer section.
- Resolved IP addresses.
- DNS server used.
- Query execution time.

### Important DNS Response

A successful DNS query commonly returns:

```text
status: NOERROR
```

This indicates that the DNS query completed successfully.

---

## 10. Step 9: Trace Network Routes Using Traceroute

If DNS resolution or network connectivity fails, examining the route to the destination can help identify where communication is interrupted.

### Command

```bash
traceroute 8.8.8.8
```

If administrative privileges are required:

```bash
sudo traceroute 8.8.8.8
```

### Explanation

`traceroute` displays the network hops packets travel through when reaching a destination.

Each hop represents an intermediate network device along the route.

### What to Observe

- The first hop is commonly the local router or gateway.
- Subsequent hops represent intermediate network devices.
- The final hop should ideally be the destination.

If the route stops unexpectedly, there may be a routing problem or an intermediate device may not respond to traceroute probes.

---

## 11. Step 10: Examine the Routing Table

The routing table determines where network packets should be forwarded.

### Command

```bash
ip route show
```

### Explanation

The command displays the system's routing information.

Look for:

- `default` – The default route used for destinations without a more specific route.
- `via` – The gateway through which packets are forwarded.
- `dev` – The network interface used.
- `src` – The source IP address.

A missing or incorrect default route can prevent communication with external networks.

---

## 12. Step 11: Monitor Network Routes Using MTR

MTR combines functionality from traceroute and ping to continuously monitor network paths and latency.

### Command

```bash
mtr --report-cycles 3 8.8.8.8
```

### Explanation

- `mtr` starts the network diagnostic tool.
- `--report-cycles 3` limits the report to three test cycles.
- `8.8.8.8` specifies the destination.

### Information Provided

MTR displays:

- Network hops.
- Packet loss percentage.
- Number of packets sent.
- Last response time.
- Average response time.
- Best and worst response times.

This information helps identify possible network delays and packet loss along a route.
