## 1. Objective

To understand how Linux manages mounted filesystems by comparing the filesystems configured in `/etc/fstab` with the filesystems currently mounted on the system.

The lab also explores `/proc/mounts` as an alternative way of viewing the live mount table.

## 2. Environment

- **Operating System:** Kali Linux
- **Platform:** Windows Subsystem for Linux 2 (WSL2)
- **Shell:** Bash
- **User:** charles

## 3. Commands Executed

### Task 1: Examine `/etc/fstab`

Command:

```bash
cat /etc/fstab
```

Output:

```text
# UNCONFIGURED FSTAB FOR BASE SYSTEM
#
# <file system> <mount point>   <type>  <options>       <dump>  <pass>
```

**Observation:**

The `/etc/fstab` file contained only its header and column descriptions. There were no filesystem entries configured in this file.

### Task 2: List Currently Mounted Filesystems

Command:

```bash
mount
```

**Observation:**

The command displayed numerous currently mounted filesystems.

Examples included:

| Mount Point | Filesystem Type | Description |
|---|---|---|
| `/` | ext4 | Main Linux filesystem |
| `/proc` | proc | Process and kernel information |
| `/sys` | sysfs | Kernel and device information |
| `/dev` | devtmpfs | Device files |
| `/dev/pts` | devpts | Pseudo-terminals |
| `/run` | tmpfs | Runtime temporary storage |
| `/mnt/c` | 9p | Windows C: drive |
| `/sys/fs/cgroup` | cgroup2 | Control groups |

### Task 3: Inspect the Live Mount Table

Command:

```bash
cat /proc/mounts
```

**Observation:**

The command displayed the live mount table maintained by the Linux kernel.

The output contained information about mounted filesystems, including their sources, mount points, filesystem types and mount options.

## 4. Comparison of Results

The `/etc/fstab` file contained no configured filesystem entries, whereas the `mount` command displayed numerous active mounts.

This demonstrates that not all mounted filesystems are configured through `/etc/fstab`.

In my WSL2 environment, several filesystems are mounted automatically to provide Linux kernel functionality and Windows integration.

The `mount` command and `/proc/mounts` provided two ways to inspect currently mounted filesystems.

## 5. Challenges Encountered

Initially, I entered:

```bash
cat/etc/fstab
```

This produced the error:

```text
-bash: cat/etc/fstab: No such file or directory
```

**Solution:**

I corrected the command by adding a space between `cat` and `/etc/fstab`:

```bash
cat /etc/fstab
```

The command then executed successfully.

## 6. Key Concepts Learned

1. `/etc/fstab` stores filesystem mount configuration.
2. The `mount` command displays currently mounted filesystems.
3. `/proc/mounts` provides access to the kernel's live mount table.
4. Linux uses virtual filesystems such as `proc`, `sysfs` and `devtmpfs`.
5. WSL2 integrates Windows resources into the Linux filesystem, as demonstrated by `/mnt/c`.

## 7. Conclusion

This practical exercise helped me understand the difference between configured filesystem mounts and currently active mounts.

I established that my Kali Linux WSL2 environment had an unconfigured `/etc/fstab` file but several active mounted filesystems.

I also learned that `/proc/mounts` provides an alternative method of inspecting the live mount table.

The exercise improved my understanding of Linux filesystem management and the interaction between Linux and Windows in a WSL2 environment.
