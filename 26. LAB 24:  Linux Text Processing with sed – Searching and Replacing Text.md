# Linux Text Processing with sed – Searching and Replacing Text

## 1. Introduction

In Linux, `sed` (Stream Editor) is a command-line utility used to search, filter, and replace text in files.

It allows users to perform text modifications without opening a file in an interactive text editor.

In this lab, I used `sed` to search for instances of `/sbin/nologin` in `/etc/passwd` and replace them with `/bin/bash`, while preserving the original file.

The modified output was redirected into a separate file called `passwd_new`.

## 2. Learning Objectives

By completing this lab, I learned how to:

1. Understand the purpose of the `sed` command.
2. Search for specific text using `grep`.
3. Replace matching text using `sed`.
4. Understand the substitution syntax.
5. Redirect command output into a new file.
6. Verify that the original file remains unchanged.
7. Understand how search patterns can match text within longer strings.

## 3. Understanding the /etc/passwd File

The `/etc/passwd` file stores basic information about Linux user accounts.

To display its contents, I executed:

```bash
cat /etc/passwd
```

Each entry contains seven fields separated by colons (`:`).

Example:

```text
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
```

The fields represent:

| Field | Description |
|---|---|
| daemon | Username |
| x | Password placeholder |
| 1 | User ID (UID) |
| 1 | Group ID (GID) |
| daemon | User information |
| /usr/sbin | Home directory |
| /usr/sbin/nologin | Login shell |

### Understanding login shells

- `/bin/bash` – Bash command interpreter.
- `/sbin/nologin` – Prevents an account from obtaining an interactive login shell.
- `/usr/sbin/nologin` – Another common location for the nologin program.

System accounts commonly use `nologin` to prevent interactive access.

## 4. Step 1: Display the Original File

Command:

```bash
cat /etc/passwd
```

This displayed the user account information stored in `/etc/passwd`.

The output showed different system accounts, including `root`, `daemon`, `www-data`, `sshd`, `xrdp`, and my own user account, `charles`.

## 5. Step 2: Search for /sbin/nologin Using grep

Before performing the replacement, I searched for occurrences of `/sbin/nologin`.

Command:

```bash
grep '/sbin/nologin' /etc/passwd
```

This displayed all lines containing the specified search string.

The results included entries such as:

```text
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
bin:x:2:2:bin:/bin:/usr/sbin/nologin
_dhcpcd:x:995:995:DHCP Client Daemon:/var/lib/dhcpcd:/sbin/nologin
```

### Explanation

- `grep` – Searches for matching text.
- `/sbin/nologin` – The search pattern.
- `/etc/passwd` – The file being searched.

## 6. Step 3: Replace Text Using sed

I used the following command to replace occurrences of `/sbin/nologin` with `/bin/bash`.

Command:

```bash
sed 's/\/sbin\/nologin/\/bin\/bash/g' /etc/passwd
```

### Understanding the command

| Component | Function |
|---|---|
| `sed` | Stream editor |
| `s` | Substitution operation |
| `\/sbin\/nologin` | Search pattern |
| `\/bin\/bash` | Replacement text |
| `g` | Global replacement on each line |
| `/etc/passwd` | Input file |

### Understanding the substitution syntax

The general syntax is:

```bash
sed 's/search_text/replacement_text/g' filename
```

The forward slash (`/`) is used as the default delimiter in the substitution expression.

The backslash (`\`) escapes forward slashes that belong to the search and replacement paths.

### Important observation

My output included:

```text
daemon:x:1:1:daemon:/usr/sbin:/usr/bin/bash
```

Instead of the expected:

```text
daemon:x:1:1:daemon:/usr/sbin:/bin/bash
```

This happened because the search pattern `/sbin/nologin` also matched the ending portion of `/usr/sbin/nologin`.

This demonstrated why understanding search patterns is important when using `sed`.

## 7. Step 4: Redirect the Modified Output into a New File

Instead of modifying the original `/etc/passwd`, I redirected the modified output into a new file.

Command:

```bash
sed 's/\/sbin\/nologin/\/bin\/bash/g' /etc/passwd > ~/passwd_new
```

### Explanation

- `sed` performs the substitution.
- `/etc/passwd` is the original input file.
- `>` redirects the output.
- `~/passwd_new` is the destination file in my home directory.

The original `/etc/passwd` was not modified.

### Understanding output redirection

| Operator | Function |
|---|---|
| `>` | Redirects output and overwrites the destination file |
| `>>` | Appends output to an existing file |

## 8. Step 5: Verify the New File

I checked whether the new file had been created successfully.


Output:

```text

```

This confirmed that the file existed and contained the redirected output.

I then displayed its contents using:

```bash

```

## 9. Step 6: Correct the Search Pattern

To ensure that the complete login-shell field was replaced correctly, I used a more precise substitution pattern.

Command:

```bash
sed 's#:/sbin/nologin$#:/bin/bash#; s#:/usr/sbin/nologin$#:/bin/bash#' /etc/passwd > ~/passwd_new
```

### Explanation

- `#` – Used as the substitution delimiter instead of `/`.
- `:` – Matches the separator before the login-shell field.
- `$` – Matches the end of a line.
- `;` – Separates two substitution expressions.

The command handles both:

```text
/sbin/nologin
/usr/sbin/nologin
```

It replaces them with:

```text
/bin/bash
```

The corrected output is saved in `passwd_new`.

## 10. Step 7: Verify the Corrected Results

To check whether any targeted nologin entries remained in the new file, I executed:

```bash
grep -E ':/sbin/nologin$|:/usr/sbin/nologin$' ~/passwd_new
```

Expected result:

```text
```

No output means there are no remaining matches for those two login-shell patterns.

To display entries ending in `/bin/bash`, I executed:

```bash
grep -E ':/bin/bash$' ~/passwd_new
```

This displayed the converted entries.

## 11. Step 8: Confirm the Original File Remains Unchanged

Finally, I searched the original `/etc/passwd` file again.

Command:

```bash
grep '/sbin/nologin' /etc/passwd
```

The original entries were still present.

This confirmed that the substitution and output redirection had not modified the original file.

## 13. Key Takeaways

From this practical exercise, I learned that:

- `grep` helps identify matching lines in files.

- Backslashes can escape special characters in search patterns.
- The `$` symbol matches the end of a line.
- Output redirection allows modified results to be saved separately.
- Precise search patterns help prevent unintended replacements.
