# Linux Lab 14.2: Non-Graphical Web Browsers

## 1. Introduction

Linux provides several command-line web browsers that allow users to access websites without using a graphical user interface (GUI).

These browsers are particularly useful when working with Linux servers that do not have a graphical desktop environment.

In this lab, I explored non-graphical web browsers and practiced navigating websites, accessing web resources, performing searches, and downloading files using a text-based interface.

**Operating System:** Kali Linux (WSL2)

**Lab Category:** Linux Administration

**Tools:** Links, Lynx, ELinks, W3m

## 2. Objectives

- Understand non-graphical web browsers.
- Install and configure text-based browsers in Linux.
- Navigate websites using keyboard commands.
- Perform web searches without a graphical browser.
- Access website links and download resources.
- Troubleshoot common browser navigation problems.

## 3. Non-Graphical Web Browsers

The exercise introduces three main categories of text-based browsers:

1. Lynx
2. Links and ELinks
3. W3m

These browsers allow users to interact with web content through a terminal.

## 4. Step 1: Install Links

First, update the package list:

```bash
sudo apt update
```

Install Links:

```bash
sudo apt install links
```

Verify the installation:

```bash
links --version
```

## 5. Step 2: Launch Links

Launch the browser:

```bash
links
```

Alternatively, open a website directly:

```bash
links https://www.google.com
```

The browser displays website content in a text-based interface.

## 6. Step 3: Navigate Websites Using the Keyboard

The following keyboard shortcuts are useful when navigating Links.

| Key | Function |
|---|---|
| Arrow keys | Move through page elements |
| TAB | Move between selectable elements |
| ENTER | Select a highlighted link or button |
| SPACE | Move down the page |
| B | Move back up the page |
| PAGE DOWN | Move down one page |
| PAGE UP | Move up one page |
| G | Enter a URL |
| Q | Quit the browser |

Links also supports mouse navigation through its menu when the terminal environment permits it.

## 7. Step 4: Access Google

Open Google directly:

```bash
links https://www.google.com
```

Google successfully loaded in the Links browser.

However, the website displayed a message indicating that the browser needed updating.

This demonstrated that although a text-based browser can establish a connection to a website, some modern websites may not display optimally in older browsers.

## 8. Step 5: Perform a Web Search

The exercise requires searching for:

```text
Intel Linux graphics drivers
```

Navigate to a search field using the arrow keys and TAB.

Enter the search query and select the search button.

Press ENTER to display the results.

Locate a suitable result related to Intel graphics drivers for Linux.

## 9. Step 6: Access Download Resources

On the graphics driver information page, locate the section containing the URL Location.

Highlight the URL and press ENTER to access the destination.

Continue navigating through the page until you find the Latest Releases section.

Locate the latest release information and select Release Notes.

## 10. Step 7: Select a Download Resource

Navigate through the available installer options.

The exercise mentions:

- Ubuntu installers
- Fedora installers
- Source code

Select an appropriate resource and press ENTER.

A text dialog should appear with options for handling the selected file.

Choose the option to save the package and specify where you want to store it.

**Note:** Do not install a graphics driver simply for practice. Always verify hardware compatibility and use trusted official sources.

## 11. Step 8: Exit Links

To exit Links, press:

```text
Q
```

Confirm the exit if prompted.

You should return to your Linux terminal.

## 13. Challenges Encountered and Solutions

During the practical exercise, I encountered several challenges while using Links.

### Challenge 1: Black Screen After Launching Links

**Problem:**

After running the `links` command, the terminal displayed a black screen, and typing text did not appear to produce any visible response.

**Investigation:**

I attempted to use the browser keyboard controls to interact with the application.

**Resolution:**

I pressed `g` to access URL navigation and continued testing the browser.

### Challenge 2: Host Not Found Error

**Problem:**

The browser displayed:

```text
Host not found
```

This happened during the initial attempt to access Google.

**Cause:**

The initial URL contained a spelling mistake in the domain name.

**Resolution:**

I corrected the website address to:

```text
https://www.google.com
```

### Challenge 3: URL Treated as a Local File Path

**Problem:**

When entering the corrected URL through the navigation dialog, Links displayed an error similar to:

```text
Error loading file:///home/charles/https://www.google.com
No such file or directory
```

**Cause:**

The URL was interpreted as a local file path instead of a web address.

**Resolution:**

Instead of entering the URL through the navigation dialog, I exited the browser and launched the website directly from the terminal:

```bash
links https://www.google.com
```

This successfully opened Google.

### Challenge 4: Google Displayed a Browser Update Message

**Problem:**

Google loaded successfully, but displayed a message indicating that the browser needed updating.

**Explanation:**

Text-based browsers may not fully support the features expected by modern websites.

**Proposed Alternative:**

Use a simpler search interface such as DuckDuckGo Lite:

```bash
links https://lite.duckduckgo.com/lite/
```

This provides a more suitable interface for text-based browsing.
