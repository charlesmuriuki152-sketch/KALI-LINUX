

## 1. Lab Overview

This lab focuses on understanding how Bash scripts receive and process command-line arguments.

The exercise involves writing a Bash script that accepts exactly one argument and prints it to standard output. The script must also display a usage message whenever it is executed without an argument or with more than one argument.

## 2. Objectives

The objectives of this lab were to:

1. Write a Bash script that accepts exactly one command-line argument.
2. Print the supplied argument to standard output.
3. Check the number of arguments supplied by the user.
4. Display a usage message when the argument requirements are not met.
5. Use conditional statements to control script execution.

## 3. Script Creation

Created a Bash script named:

`argument.sh`

Command used:

```bash
nano argument.sh
```

### Script Contents

```bash
#!/bin/bash

# Check whether exactly one argument was provided
if [ "$#" -ne 1 ]; then
    echo "Usage: $0 <argument>"
    exit 1
fi

# Print the supplied argument
echo "$1"
```

## 4. Making the Script Executable

After writing and saving the script, executable permissions were granted using:

```bash
chmod +x argument.sh
```

The script can then be executed using:

```bash
./argument.sh
```

## 5. Understanding the Script

### Checking the Number of Arguments

```bash
if [ "$#" -ne 1 ]; then
```

This condition checks whether the number of arguments supplied is not equal to one.

- `$#` represents the number of arguments supplied.
- `-ne` means not equal to.
- `1` represents the required number of arguments.

If the condition is true, the script displays a usage message.

### Displaying the Usage Message

```bash
echo "Usage: $0 <argument>"
exit 1
```

- `echo` displays the usage instructions.
- `$0` represents the script name or execution path.
- `exit 1` terminates the script and indicates an error.

### Printing the Argument

```bash
echo "$1"
```

`$1` represents the first command-line argument supplied by the user.

The script prints that argument to standard output.

## 6. Testing the Script

Three test cases were used to demonstrate how the script handles different argument conditions.

### Test 1: Executing Without an Argument

Command:

```bash
./argument.sh
```

Expected output:

```text
Usage: ./argument.sh <argument>
```

**Observation:**

The script displays a usage message because no argument was provided.

It terminates with an error status.

### Test 2: Executing With Exactly One Argument

Command:

```bash
./argument.sh Hello
```

Expected output:

```text
Hello
```

**Observation:**

The script accepts the single argument and prints it to standard output.

### Test 3: Executing With More Than One Argument

Command:

```bash
./argument.sh Hello Charles
```

Expected output:

```text
Usage: ./argument.sh <argument>
```

**Observation:**

The script rejects the additional argument because it requires exactly one argument.
