# Kali Linux XRDP Audio Troubleshooting Lab

## Objective
Fix silent YouTube playback in Firefox ESR during a Kali Linux XRDP session and configure a reusable launcher.

## Environment
- OS: Kali Linux
- User: `charles`
- XRDP: `0.10.6.1-2+kali1`
- PipeWire / pipewire-pulse: `1.6.8-1`
- WirePlumber: `0.5.15-1`
- PulseAudio: `17.0+dfsg1-3`
- XRDP audio module: `0.6-0kali2+b1`
- Display: `:18.0`
- Audio sink: `xrdp-sink`
- Audio socket: `/tmp/pw-test/pulse/native`

## 1. Problem
YouTube played in Firefox, but no sound was heard through the XRDP session.

## 2. Diagnosis
The XRDP audio route worked: a test tone was audible. However, Firefox did not appear in the audio server's active playback streams.

The required environment variables were:

```bash
export XDG_RUNTIME_DIR=/tmp/pw-test
export PULSE_SERVER=unix:/tmp/pw-test/pulse/native

Changing these variables in a terminal does not update an already-running Firefox process.

3. Check the Audio Server
export XDG_RUNTIME_DIR=/tmp/pw-test
export PULSE_SERVER=unix:/tmp/pw-test/pulse/native
pactl info
pactl list short sinks

Expected sink: xrdp-sink.

4. Check Active Audio Streams

Play a video, then run:

pactl list sink-inputs short
A listed stream means the audio server sees an application playback stream.
An empty result means no playback stream is currently reported.
5. Test the XRDP Audio Route
paplay --server="$PULSE_SERVER" --device=xrdp-sink /tmp/xrdp-audio-test.wav

Result: The test tone was audible, confirming that the output route worked for this test.

6. Fix Firefox

Close Firefox, then relaunch it with the correct environment:

XDG_RUNTIME_DIR=/tmp/pw-test \
PULSE_SERVER=unix:/tmp/pw-test/pulse/native \
firefox-esr

Result: YouTube audio worked after Firefox was restarted with the correct environment.

7. Create a Dedicated Firefox Launcher

File: ~/.local/bin/firefox-xrdp

#!/bin/bash
export XDG_RUNTIME_DIR=/tmp/pw-test
export PULSE_SERVER=unix:/tmp/pw-test/pulse/native
exec /usr/bin/firefox-esr "$@"

Make it executable:

chmod +x ~/.local/bin/firefox-xrdp

A desktop-menu entry was created at:

~/.local/share/applications/firefox-xrdp.desktop

Its application name is Firefox ESR (XRDP Audio).

Use this launcher to start Firefox with the required audio settings.

8. Automatic Startup

A startup script was created at:

~/.local/bin/xrdp-audio-start

An autostart entry was created at:

~/.config/autostart/xrdp-audio.desktop

The script attempts to connect to the audio server and start PulseAudio if necessary.

9. Persistence Warning

The configuration has not been fully verified after reboot or XRDP reconnection.

The socket is located under /tmp, which may be cleared during reboot. The startup script does not guarantee that XRDP audio modules and sockets will be recreated correctly.

Test after a full XRDP disconnect/reconnect and reboot before considering the setup permanent.

10. Troubleshooting Checklist
Play a test tone through the XRDP sink.
Check pactl info and pactl list short sinks.
Check active streams with pactl list sink-inputs short.
Verify the application's audio environment.
Restart the application with the correct environment variables.
Create a dedicated launcher.
Test after XRDP reconnection and reboot.
