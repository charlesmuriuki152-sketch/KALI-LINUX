Introduction

In this Linux troubleshooting lab, I investigate an audio problem in Mozilla Firefox running on Kali Linux under Windows Subsystem for Linux 2 (WSL2).

The problem was that YouTube audio did not work when Firefox was launched normally. I tested the WSLg audio system, inspected the available audio devices, ran audio playback tests, and attempted to configure Firefox to use the correct audio server.

💻 Topics Covered

- Running Kali Linux on Windows using WSL2
- Understanding WSLg audio integration
- Testing Linux audio playback using "paplay"
- Inspecting audio sinks using "pactl"
- Troubleshooting Firefox ESR audio problems
- Using environment variables to configure Firefox
- Stopping Firefox processes during troubleshooting
- Creating a custom Firefox launcher
- Modifying a Linux desktop application entry
- Documenting troubleshooting results and unresolved issues

🛠️ Commands Used During Troubleshooting

1. Check the Linux environment

cat /proc/version

2. Inspect the WSL configuration

cat /etc/wsl.conf

3. Check WSLg audio components

ls /mnt/wslg/

4. Test audio playback

paplay /usr/share/sounds/alsa/Front_Center.wav

5. Inspect available audio sinks

pactl list short sinks

6. Check active audio playback streams

pactl list short sink-inputs

7. Check the Firefox installation and version

which firefox
firefox --version

8. Stop running Firefox ESR processes

pkill firefox-esr

Purpose: Stops running Firefox ESR processes before testing a new launch configuration. Unsaved browser work may be lost.

9. Launch Firefox with working audio

export PULSE_SERVER=unix:/mnt/wslg/PulseServer
export MOZ_ENABLE_WAYLAND=1
firefox

10. Create the custom Firefox audio launcher

sudo tee /usr/local/bin/firefox-audio >/dev/null <<'EOF'
#!/bin/sh
export PULSE_SERVER=unix:/mnt/wslg/PulseServer
export MOZ_ENABLE_WAYLAND=1
exec /usr/lib/firefox-esr/firefox-esr "$@"
EOF

sudo chmod +x /usr/local/bin/firefox-audio

11. Configure the desktop application entry

mkdir -p ~/.local/share/applications
cp /usr/share/applications/firefox-esr.desktop ~/.local/share/applications/

The desktop entry's main "Exec" line was changed to:

Exec=/usr/local/bin/firefox-audio %u

Verify the entry using:

grep '^Exec=' ~/.local/share/applications/firefox-esr.desktop

⚠️ Errors and Unresolved Issues

- The ALSA test returned "Unknown PCM pulse".
- No active audio streams appeared in the "pactl" sink-input listing during inspection.
- YouTube audio worked when Firefox was launched from the terminal with the specified environment variables.
- YouTube audio still did not work when Firefox was launched from the desktop applications menu, even after modifying the desktop launcher.

✅ Results

The WSLg audio path was functional, as demonstrated by the successful "paplay" test. Firefox audio was restored for terminal launches using the explicit environment variables.

📚 Conclusion and Lab Status

Status: Partially Successful

Terminal audio playback was restored, but the desktop-launch audio issue remained unresolved.
